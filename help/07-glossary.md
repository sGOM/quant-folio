# 07. 용어 사전 — 퀀트 · 증권 도메인

개발은 익숙해도 증권 도메인이 낯설면 코드의 "왜" 가 안 보인다. 코드에 자주 나오는
용어만 추렸다. (전략별 상세 수식은 `docs/strategies.md`)

## 거래 기본

| 용어 | 뜻 | 코드 등장 |
|------|-----|-----------|
| **종목코드(symbol)** | 6자리 KRX 코드. 예: 삼성전자 `005930` | 거의 모든 곳 |
| **현재가(quote)** | 지금 거래되는 가격 | `Quote`, `get_quote` |
| **호가** | 사자/팔자 대기 가격 | (이 프로젝트는 시장가 위주) |
| **시장가(market)** | 가격 안 정하고 "지금 즉시 체결" 주문 | `place_order(order_type="market")` |
| **지정가(limit)** | "이 가격 이하/이상일 때만" 주문 | `ORD_DVSN "00"` |
| **매수(buy)/매도(sell)** | 사기/팔기 | `OrderSide` |
| **체결(execution/fill)** | 주문이 실제로 거래 성사됨 | `Execution`, `Fill` |
| **미체결** | 접수됐지만 아직 안 팔림/안 사짐 | `OrderStatus.SUBMITTED` |
| **포지션(position)** | 현재 보유 중인 종목·수량·평균단가 | `Position` |
| **평균단가(avg_price)** | 보유분의 매입 평균 가격 | `Position.avg_price` |
| **OHLCV** | 시(Open)·고(High)·저(Low)·종(Close)·거래량(Volume) — 하루 봉의 5요소 | `price_ticks` |
| **일봉** | 하루를 한 칸으로 본 캔들. 이 프로젝트는 일봉 기준 | `load_ohlcv` |

## 주문 상태 (`OrderStatus`)

```
PENDING   엔진이 주문 생성, 아직 KIS 전송 전
SUBMITTED KIS 가 접수함(아직 체결 전일 수 있음)
PARTIAL   일부만 체결
FILLED    전량 체결
CANCELLED 취소됨
REJECTED  거부됨(잔고부족·장종료 등)
```

## 성과 지표 (백테스트 결과)

| 지표 | 뜻 | 직관 |
|------|-----|------|
| **수익률(total_return)** | 기간 총 손익률 | 높을수록 좋음 |
| **CAGR** | 연평균 복리 성장률(기간 길이로 연율화) | 기간이 달라도 비교 가능 |
| **MDD(최대낙폭)** | 고점 대비 가장 크게 빠진 비율 | **낮을수록** 좋음(고통의 크기) |
| **샤프지수(Sharpe)** | 위험(변동성) 1단위당 **무위험이자율 초과** 수익 | 높을수록 효율적. 보통 1↑ 양호 |
| **소르티노(Sortino)** | 샤프의 하방 위험 버전(하락 변동성만 벌점) | 상승 변동성은 봐주므로 샤프보다 관대 |
| **승률(win_rate)** | 이긴 매매 비율 | 참고용(승률 높아도 손실 클 수 있음) |
| **자산곡선(equity curve)** | 시간에 따른 계좌 평가액 추이 | 우상향이 이상적 |

> **MDD 가 왜 중요한가**: 수익률이 같아도 MDD 가 크면 중간에 멘탈/자금이 못 버텨
> 전략을 포기하게 된다. 그래서 수익률만큼 낙폭을 본다.

## 벤치마크 상대 지표 (`attribution.py`)

수익률만 보면 "시장이 좋아서 번 것"과 "전략이 잘해서 번 것"을 구분 못 한다.
KOSPI200을 벤치마크로 두고 **시장 대비** 실력을 떼어 본다.

| 지표 | 뜻 | 직관 |
|------|-----|------|
| **벤치마크수익(benchmark_return)** | 같은 기간 KOSPI200 수익률 | 비교 기준선 |
| **초과수익(excess_return)** | 전략수익 − 벤치마크수익 | 시장을 이겼나(단순 차이) |
| **베타(beta)** | 시장이 1% 움직일 때 전략이 몇 % 움직이나 | 1↓ = 방어형(시장 덜 탐), 1↑ = 공격형 |
| **알파(alpha)** | 베타로 설명 안 되는 **순수 실력** 초과수익(연율) | 진짜 실력. **양(+)이 핵심** |
| **정보비율(IR)** | 초과수익을 그 변동성(추적오차)로 나눈 값 | 초과수익의 효율·일관성 |
| **추적오차(tracking_error)** | 전략과 벤치마크 수익 차이의 변동성 | 클수록 벤치마크와 딴판 |

> **주의 — `tracking_error`는 이 코드베이스에서 두 군데에 나온다.** 위 표(`attribution.py`)는
> **전략 vs 벤치마크(KOSPI200)** 이고, 트래킹 API(`services/backtest/tracking.py`)의
> 동명 지표는 **모의투자 실측 vs 백테스트 기대곡선**이다. 후자는 "백테스트대로 실제로
> 돌고 있나"를 보는 것이라 목적이 다르다 — 크면 체결가·타이밍·유니버스가 어긋났다는 신호.

> **저베타 전략은 초과수익으로 판정하면 안 된다**: 강세장에서는 시장을 덜 타는
> 방어형(β<1)이 벤치마크에 뒤처져 초과수익이 (−)로 보일 수 있다. 이때도 **알파가
> (+)면 실력은 살아있는 것**. 방어형은 `alpha`·`Sharpe`로, 공격형은 `excess`·`IR`로 본다.

## 성과귀속 · 팩터 예측력 (`attribution.py`)

멀티팩터 전략이 "어느 팩터 덕에/때문에" 이렇게 됐는지 분해한다.

| 용어 | 뜻 |
|------|-----|
| **팩터(factor)** | 수익을 설명하는 특성 축. 이 프로젝트는 5개: 모멘텀·밸류·저변동·퀄리티·성장 |
| **IC(정보계수)** | 팩터 점수와 **다음 구간 실현수익**의 순위상관. 예측력의 부호·강도 |
| **팩터 IR** | IC의 평균/표준편차. 그 예측력이 **얼마나 일관적**인가 |
| **롱숏수익** | 팩터 상위군 매수·하위군 매도 시 수익. 팩터의 실질 기여 |
| **사이즈 중립화** | 소형주 쏠림(사이즈 틸트)을 제거해 팩터 순수 효과만 남김 |

> 모멘텀 IR이 (−)면 그 팩터는 이 유니버스에서 **역효과**라는 뜻. 비중을 빼는 근거가 된다.

## 체결 모델 · 거래비용 (백테스트 현실성)

| 용어 | 뜻 | 코드 |
|------|-----|------|
| **익일 종가 체결** | 신호는 당일 종가로 잡되 **다음 날 종가**로 체결(미래참조 차단) | 리밸런싱 시뮬 루프 |
| **슬리피지(slippage)** | 원하는 가격과 실제 체결가의 괴리(불리하게 밀림) | `slippage_bps`, `slippage.py` |
| **변동성 스케일 슬리피지** | 변동성 큰 종목일수록 슬리피지를 키워 현실 반영 | `slippage_vol_scale` |
| **bps(베이시스포인트)** | 0.01% = 1bp. 수수료·슬리피지 단위 | `slippage_bps` |
| **거래비용** | 수수료 + 세금(매도 시) + 슬리피지 총합 | 백테스트에 반영 |

## 리스크 레이어 (`risk_caps.py`, 리밸런싱)

목표 비중을 실제 발주 전에 한 번 더 다듬는 안전장치들.

| 용어 | 뜻 | 코드 |
|------|-----|------|
| **집중 한도** | 한 종목 목표비중 상한. 초과분은 다른 종목에 재분배 | `max_weight_per_name`, `_cap_position_weights` |
| **변동성 타겟팅** | 포트폴리오 변동성을 목표치로 맞춰 비중을 일괄 스케일 | `target_vol` |
| **MDD 킬스위치** | 누적 낙폭이 한계 넘으면 청산(백테스트 전용) | 시뮬 루프 |

## 리스크 관리 (`risk_limits`, 전략 config)

| 용어 | 뜻 | 코드 |
|------|-----|------|
| **손절(stop loss)** | 손실이 일정%면 강제 매도해 더 큰 손실 차단 | `stop_loss_pct`, `check_stop_loss` |

## 기술적 지표 (신호에 쓰임)

| 지표 | 한 줄 설명 | 신호 |
|------|------------|------|
| **SMA/EMA** | 단순/지수 이동평균(가격을 매끄럽게) | 골든크로스(단기↑장기)=매수 |
| **RSI** | 0~100, 과매수(70↑)/과매도(30↓) 측정 | 과매도 탈출=매수 |
| **MACD** | 두 EMA 의 차이로 추세·모멘텀 | 시그널선 상향돌파=매수 |
| **볼린저밴드** | 이동평균 ± 표준편차 밴드 | 하단 복귀=매수(평균회귀) |
| **ATR** | 평균 진폭(변동성 크기) | 트레일링/채널 폭 산정 |
| **돌파(breakout/Donchian)** | 최근 N봉 최고가 돌파 | 돌파=매수(추세추종) |
| **모멘텀** | 과거 대비 가격 추세 | 양전환=매수 |
| **스토캐스틱** | 고저 범위 내 현재가 위치(%) | 과매도 교차=매수 |
| **OBV** | 거래량으로 매집/분산 추적 | 추세 확인 |

> **평균회귀 vs 추세추종**: 볼린저·RSI·z-score 는 "빠지면 돌아온다"(평균회귀),
> 돌파·모멘텀·ATR트레일링은 "오르면 더 간다"(추세추종). 정반대 철학이라 시장 국면에
> 따라 잘 맞는 게 다르다.

## 백테스트 방법론 · 유니버스 (전략 검증의 함정)

전략이 "진짜"인지 판정하는 규율. 여기를 틀리면 백테스트 수익은 다 신기루다.

| 용어 | 뜻 | 왜 중요한가 |
|------|-----|------------|
| **미래참조(look-ahead)** | 그 시점엔 알 수 없던 정보로 매매했다고 계산 | 현실 불가능한 가짜 수익 → 익일 체결로 차단 |
| **과최적화(overfitting)** | 과거에만 딱 맞게 파라미터를 쥐어짬 | 미래엔 무너짐. 파라미터 적을수록 건강 |
| **생존편향(survivorship bias)** | 지금 살아남은 종목만으로 과거를 검증 | 상장폐지·탈락 종목 누락 → 성과 과대 |
| **PIT(시점 정확)** | 각 시점에 **실제로 그 지수에 있던** 구성종목으로 검증 | 생존편향 제거. 신규 전략은 반드시 PIT로 |
| **유니버스(universe)** | 전략이 매매 대상으로 삼는 종목 풀 | 손질된 풀은 성과 붕괴(편향) |
| **레짐(regime)** | 시장 국면(강세/약세). 진입·청산을 스위칭 | `exit_buffer`로 휩쏘(whipsaw) 회피 |
| **리밸런싱(rebalance)** | 주기적으로(예: 분기) 목표비중 재계산·교체 | 멀티팩터 전략의 운용 축 |
| **TTM(트레일링 4분기)** | 최근 4개 분기를 합산한 실적(매출·순이익 등) | 연간 실적보다 **신선**. 단 공시 지연(lag)을 지켜야 PIT |

> **신규 전략 검증은 반드시 PIT KOSPI200 유니버스로**. 손질된(생존한 종목만 남긴)
> 풀에서는 성과가 부풀려지고, PIT로 바꾸면 대부분 붕괴한다. (`docs/strategies.md`)

> **PIT는 구성종목만의 문제가 아니다.** 재무지표(OpenDART)는 공시 지연을 반영해
> "그 시점에 이미 공시된 보고서"만 쓰고(`latest_report_period`), 업종분류는 KRX가
> 현재 분류만 줘서 **분기 스냅샷을 적재한 시점 이후 구간부터** PIT가 된다
> (`sector_map_snapshots`). 스냅샷 이전 과거 구간은 현재 분류로 근사하는 약한
> look-ahead가 남아 있다 — 캡(비중 상한) 용도라 왜곡은 제한적이라는 판단.

## KIS API 용어

| 용어 | 뜻 |
|------|-----|
| **App Key / App Secret** | KIS 발급 API 자격증명(= Spring 의 client_id/secret) |
| **접근토큰(access token)** | 발급 후 24시간 유효. 분당 1회 발급 제한 → Redis 캐싱 |
| **approval_key** | 실시간(WebSocket) 시세 인증용 키 |
| **tr_id** | API 거래 식별 코드. 모의(`VTTC...`)/실전(`TTTC...`)이 다름 |
| **hashkey** | 주문 body 변조 방지 해시 |
| **모의투자(vts)** | 실거래와 똑같은 인터페이스의 **가짜 돈** 환경. 기본값 |
| **CANO / ACNT_PRDT_CD** | 계좌번호 앞 8자리 / 상품코드 2자리(`50012345-01`) |

## 멱등성 & 동시성 (개발 용어지만 이 프로젝트 맥락)

| 용어 | 이 프로젝트에서 | 
|------|------------------|
| **멱등성(idempotency)** | 같은 신호로 몇 번 시도해도 주문은 한 번만 — 이중 매수 방지 |
| **멱등성 키** | `s{전략}:{종목}:{side}:{신호봉날짜}` 결정적 문자열 |
| **분산 락(SET NX)** | 여러 프로세스/코루틴 중 하나만 임계영역 진입 |
| **TOCTOU** | "확인하고-쓰는" 사이 경합. 포지션 락으로 직렬화해 방지 |
| **슬라이딩 만료** | 활동 있으면 TTL 갱신(세션·가격캐시) |
| **하트비트** | 살아있음 신호. 엔진이 주기적으로 Redis 키 갱신 |
