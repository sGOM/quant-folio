# QuantFolio 로드맵

작성일: 2026-07-19

## 이 문서의 성격

- **목표(무엇을·왜)를 공유하는 문서**다. 구현 방식(어떤 라이브러리·어떤 스키마·어떤
  프로세스 구조)은 의도적으로 **추상적으로만** 적는다 — 스택이나 아키텍처가 바뀌어도
  이 문서의 목표는 그대로 유효해야 한다.
- 구체적 구현 계획·완료 현황은 [`docs/improvements.md`](improvements.md)(단기 개선안
  트래킹)와 각 PR이 담당한다. 이 문서는 마일스톤이 **끝났는지/방향이 바뀌었는지**만
  갱신한다.
- 순서는 권장 우선순위지만, 마일스톤 간 의존이 명시된 경우를 제외하면 병행·역전 가능.

## 비전 (한 문장)

> 개인 투자자 여러 명이 각자의 계좌로, 검증된 퀀트 전략을 안심하고 24시간 자동
> 운용하며, 시장 맥락(뉴스·지표)까지 한 화면에서 파악할 수 있는 플랫폼.

---

## M1. 실전 투자 전환 완성

**목표**: 모의투자에서 검증된 운용 체계를 실계좌에서 동일한 신뢰도로 돌린다.

- 실계정 환경에서만 검증 가능한 가정들(체결통보 해석 방식 등)을 실측으로 확정한다.
- 운영 DB의 과거 데이터 정합(포지션 귀속 등)을 감사하고, 실전 전환 체크리스트를
  통과한 전략만 실계좌 운용을 허용한다.
- 소액 시험 운용 기간을 두어 백테스트·모의투자 대비 실측 괴리(슬리피지·체결 품질)를
  측정하고, 허용 범위를 벗어나면 자동으로 방어(축소·중단)하는 안전장치를 갖춘다.

**완료 기준**: 대표 전략 1개 이상이 실계좌에서 1개월 이상 무사고 운용되고, 실측
괴리가 사전에 정한 허용 범위 안에 있다.

## M2. 다중 사용자 동시 접속 서버 구축 ★필수

**목표**: 한 대의 노트북에서 상시 구동되는 서버에 여러 사용자가 동시에 접속해,
각자 독립된 전략·계좌·데이터로 플랫폼을 사용할 수 있다.

- **사용자 격리**: 사용자별로 전략·주문·포지션·알림·브로커 인증정보가 완전히
  분리되고, 서로의 데이터를 볼 수 없다. 브로커 API 키는 사용자 단위로 등록·암호화
  보관한다.
- **외부 접근**: 가정용 네트워크의 노트북에서도 외부에서 안전하게(암호화된 연결로)
  접속할 수 있는 진입점을 마련한다. 방식(도메인+포트포워딩, 터널링 서비스 등)은
  운영 환경에 맞게 선택하되, 인증 없는 노출면이 없어야 한다.
- **상시 가용성**: 노트북 특성(절전·재부팅·전원 단절)을 전제로, 서버가 꺼졌다
  켜져도 매매 엔진과 데이터가 스스로 복구되는 무인 운영 체계를 갖춘다. 장 중
  다운타임은 감지·통보된다.
- **동시성·자원 한도**: 소수(예: 10인 이하) 동시 사용자를 가정하고, 무거운 작업
  (백테스트 등)이 실시간 매매를 방해하지 않도록 자원을 격리·제한한다. 브로커
  API 호출 한도를 사용자 간 공정하게 배분한다.
- **운영자 권한**: 계정 관리(초대·비활성화)와 시스템 상태 조회는 운영자 역할로
  분리한다.

**완료 기준**: 서로 다른 기기의 사용자 2인 이상이 외부망에서 동시 접속해 각자의
전략을 등록·운용하고, 상대방의 데이터에 접근할 수 없음이 확인된다. 서버 재부팅
후 개입 없이 정상 상태로 복귀한다.

## M3. 경제 뉴스 통합 — 수집·요약·종목 연계 ★필수

**목표**: 경제 관련 기사를 자동 수집해 **요약과 원문 링크**를 보여주는 뉴스 메뉴를
제공하고, **종목을 선택하면 그 종목의 관련 기사**가 함께 표시된다.

- **수집**: 신뢰할 수 있는 출처(언론사 RSS·공개 API 등)에서 경제·증시 기사를
  주기적으로 수집한다. 출처의 이용 약관을 준수하고, 본문 전재가 아닌 요약+링크
  방식으로 표시한다.
- **요약**: 기사별 짧은 요약을 생성해 목록에서 훑어볼 수 있게 한다. 요약 생성
  수단(LLM, 추출 요약 등)은 교체 가능해야 한다.
- **종목 연계**: 기사를 관련 종목에 매핑(종목명·종목코드 언급 기반)해, 종목 상세
  화면·스크리너에서 해당 종목의 최근 기사를 바로 볼 수 있게 한다.
- **확장 여지**: 수집이 안정화되면 뉴스를 전략 신호·리스크 판단(예: 패닉 지표의
  정성 보조)에 활용하는 것을 후속 과제로 검토한다 — 단, 이 단계의 범위는 아님.

**완료 기준**: 뉴스 메뉴에서 최신 경제 기사 목록(요약+링크)이 보이고, 임의의
보유·관심 종목을 선택하면 그 종목의 관련 기사가 표시된다. 수집 실패 시 알림으로
감지된다.

## M4. 전략 리서치 고도화 (상시 트랙)

**목표**: 대표 전략의 우위를 유지·확장하고, 새 전략 후보를 규율 있게 검증한다.

- 모든 신규 검증은 **생존편향이 제거된(PIT) 유니버스**에서 수행한다는 원칙을
  유지한다. 방어형 전략의 판정 지표 규약(alpha/Sharpe)도 유지한다.
- 이미 배선된 개선 경로들(재무 반영 주기, 체결 현실성 모델, 섹터 중립화 등)의
  효과를 A/B로 확정하고, 채택/기각을 문서에 기록한다.
- 유니버스 확장(코스닥·중형주 등), 새 데이터 소스, 전략 간 자본 배분(포트폴리오
  오브 스트래티지) 같은 다음 단계 주제를 탐색한다.

**완료 기준**: 상시 트랙이므로 종결 없음. 분기마다 검증 결과가 전략 문서에
누적되는 것으로 갈음한다.

## M5. 운영 안정성·관측성 성숙

**목표**: 여러 사용자의 실계좌가 걸린 시스템으로서, 문제를 사용자보다 먼저 알고
데이터를 잃지 않는다.

- 핵심 상태(엔진 생존, 데이터 적재, 백업 신선도, 체결 품질)의 감시와 알림을
  다중 사용자 환경 기준으로 확장한다.
- 백업은 기기 밖(오프사이트)에도 복제되고, 복원 절차가 실제로 리허설된다.
- 장애·오동작의 사후 분석이 가능하도록 주문·체결·판단 근거의 감사 이력을 남긴다.

**완료 기준**: 오프사이트 백업에서 전체 복원 리허설 1회 성공, 주요 장애 시나리오
(엔진 중단·데이터 적재 실패·백업 실패)가 모두 자동 통보됨.

|------|----------|------|

| 2 | M2 다중 사용자 서버 ★ | M1의 안전장치가 있어야 타인 계좌를 받을 수 있음 |
