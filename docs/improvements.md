## 1. fill_notice 실계정 검증 (실전 전환 전 필수)

`engine/fill_notice.py` 는 **실계정으로 검증되지 않은 설계 가정 3개**를 명시적으로 안고 있다
(모듈 docstring 참고):

- CNTG_QTY 를 "누적 체결수량"으로 간주한 델타 반영 — 증분수량으로 밝혀지면 로직 수정 필요.
- 체결통보 프레임에 ORGNO 미노출 가정 — ODNO 단독 매칭.
- `_parse_fill_notice` 필드 인덱스가 공식 샘플 순서 기준(종단 미검증).

→ `docs/live-order-guide.md` §2-1-A 실계정 전환 체크리스트로 검증한다. 실전(prod) 전환의
마지막 관문.

## 2. 마이그레이션 0008 백필 감사 (id=23+24 병행 운용 전 필수)

절차는 `docs/live-order-guide.md`에 문서화 완료. **실DB 실행·감사는 운영 시점 작업**:
`alembic upgrade head` 후 positions의 `strategy_id` NULL 잔존 행을 뽑아 수동 귀속 여부 판단.

## 3. 프론트 테스트 확대 — 훅·컴포넌트

순수 유틸(`lib/format`·`lib/strategy`·`lib/api`)과 `strategy-form/validate`는 커버됨. 다음 단계:

- TanStack Query 훅(모킹된 fetch로 상태 전이), WebSocket 재연결 훅.
- 핵심 표시 컴포넌트(손익 색상·등급 배지, TradeLogTable) 렌더 테스트.

## 4. 데이터 계층 확장 (OpenDART 잔여)

`docs/opendart-integration.md` "아직 남은 확장" 참고:

- 분기 **TTM**(트레일링 4분기) 지표로 팩터 신선도 향상(현재 연간 기준).
- 이익추정치 리비전은 무료 API 부재 → 발표 실적 YoY 서프라이즈 근사 유지.
- 상폐 포함 PIT 유니버스(KIND 스크래핑)는 별도 과제 — 현재는 PIT KOSPI200 구성으로 대체 중.

## 5. 리스크 레이어 보류 항목

- **섹터 집중 한도**: 신뢰할 수 있는 섹터 매핑 데이터 부재로 보류(risk_layer 구현 시 명시).
- **MDD 킬스위치 실거래 배선**: 현재 백테스트 전용 — 실거래 도입 시 재가동 절차(수동 해제)
  설계 필요.
